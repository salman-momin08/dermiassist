## 1. Enable pgvector Extension

The `pgvector` extension adds vector datatype support and similarity search algorithms (cosine distance, L2 distance, inner product) to PostgreSQL.

### Steps to Enable:

1. Open your [Supabase Dashboard](https://supabase.com/dashboard).
2. Select your DermiAssist-AI project.
3. Navigate to **SQL Editor** in the left sidebar.
4. Run the following SQL command:

```sql
-- Enable pgvector extension
CREATE EXTENSION IF NOT EXISTS vector;
```

## 2. Create Medical Knowledge Vector Table

Next, create the `medical_knowledge_chunks` table to store clinical passages alongside 768-dimensional embeddings generated by Google Gemini (`text-embedding-004`).

Run the following SQL snippet:

```sql
-- Create table for medical knowledge vector chunks
CREATE TABLE IF NOT EXISTS medical_knowledge_chunks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title TEXT NOT NULL,
    condition_category TEXT NOT NULL,
    content TEXT NOT NULL,
    source TEXT NOT NULL,
    icd_code TEXT,
    metadata JSONB DEFAULT '{}'::jsonb,
    embedding vector(768), -- 768 dimensions for Gemini text-embedding-004
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Create IVFFlat cosine similarity index for fast vector search
CREATE INDEX IF NOT EXISTS idx_medical_knowledge_embedding 
ON medical_knowledge_chunks 
USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100);

-- Create B-Tree index on condition category
CREATE INDEX IF NOT EXISTS idx_medical_knowledge_category 
ON medical_knowledge_chunks (condition_category);

-- Enable Row Level Security (RLS)
ALTER TABLE medical_knowledge_chunks ENABLE ROW LEVEL SECURITY;

-- Allow public/authenticated read access for RAG queries
CREATE POLICY "Allow public read on medical knowledge" 
ON medical_knowledge_chunks FOR SELECT USING (true);
```

## 3. Create Vector Similarity Search Function (RPC)

Create the PostgreSQL stored procedure `match_medical_knowledge` to perform cosine similarity matching with score thresholding and category filtering:

```sql
CREATE OR REPLACE FUNCTION match_medical_knowledge (
  query_embedding vector(768),
  match_threshold float,
  match_count int,
  category_filter text DEFAULT NULL
)
RETURNS TABLE (
  id UUID,
  title TEXT,
  condition_category TEXT,
  content TEXT,
  source TEXT,
  icd_code TEXT,
  similarity float
)
LANGUAGE plpgsql
AS $$
BEGIN
  RETURN QUERY
  SELECT
    mkc.id,
    mkc.title,
    mkc.condition_category,
    mkc.content,
    mkc.source,
    mkc.icd_code,
    1 - (mkc.embedding <=> query_embedding) AS similarity
  FROM medical_knowledge_chunks mkc
  WHERE (category_filter IS NULL OR mkc.condition_category = category_filter)
    AND 1 - (mkc.embedding <=> query_embedding) > match_threshold
  ORDER BY mkc.embedding <=> query_embedding
  LIMIT match_count;
END;
$$;
```

## 5. Testing & Verifying Vector Search

### Option 1: Test via Supabase SQL Editor

Run a similarity query against a test vector embedding:

```sql
SELECT 
    title, 
    condition_category, 
    source, 
    1 - (embedding <=> '[0.01, 0.02, ...]'::vector) AS similarity
FROM medical_knowledge_chunks
ORDER BY similarity DESC
LIMIT 3;
```

### Option 2: Test via AI Control Center UI

1. Start your Next.js server (`npm run dev`).
2. Navigate to `http://localhost:9002/admin/ai-engineering`.
3. Open the **Multi-Agent Engine** tab and run a test query. The pipeline will query `pgvector` and output grounded citations!

## 6. Troubleshooting & FAQs

### Q1: `extension "vector" is not available`
**Fix**: Ensure your Supabase project PostgreSQL version is 15 or higher. In older database instances, contact Supabase support to enable `pgvector`.

### Q2: `dimension mismatch error (768 vs 1536)`
**Fix**: DermiAssist-AI uses Google Gemini `text-embedding-004`, which outputs **768 dimensions**. Ensure your vector column is defined as `vector(768)`.

### Q3: `permission denied for schema public`
**Fix**: Run `GRANT ALL ON TABLE medical_knowledge_chunks TO service_role;` in the Supabase SQL Editor.
